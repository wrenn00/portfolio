개요

첫 출근을 앞둔 사용자는
채용 이후의 과정을 스스로 해결해야 합니다

알바몬은 사용자가 자신에게 맞는 일자리를 빠르게 발견하고 지원할 수 있도록 채용과 매칭 경험을 발전시켜 왔습니다. 하지만 채용이 완료된 이후 반드시 진행되어야 하는 근로계약 과정은 기존 채용 흐름과 분리되어 있었습니다. 근로계약서 기능은 이미 제공되고 있었지만, 기능의 위치가 잘 드러나지 않았고 채용 완료 이후 자연스럽게 계약 작성으로 연결되는 진입점도 부족했습니다. 이 때문에 사용자는 계약서를 직접 찾아야 했으며, 작성 시점을 놓치거나 계약 없이 근무를 시작하는 상황이 반복되고 있었습니다. 이 프로젝트는 근로계약서를 단순히 작성하는 기능이 아니라, 채용을 실제 근무로 연결하는 첫 번째 관리 경험으로 바라보는 것에서 시작했습니다.

문제 발견

근로계약서 미작성은 개인의 실수가 아니라
반복되는 구조적 문제입니다

데스크 리서치를 통해 알바생 3명 중 1명이 근로계약서를 작성하지 않고 있으며, 단기 알바의 미작성률은 절반 이상이라는 사실을 확인했습니다. 미작성 이유 중 가장 높은 비율을 차지한 것은 ‘사업자가 안내하지 않아서’였습니다. 이는 사용자가 근로계약의 중요성을 몰라서라기보다, 계약을 시작하도록 알려주고 행동을 유도하는 구조가 부족하다는 의미였습니다. 근로계약서 미작성은 이후 임금, 근로시간, 업무 범위에 대한 분쟁으로 이어질 수 있습니다. 알바생에게는 권리를 증명할 근거가 사라지고, 사장님에게는 법적 위험과 갈등 비용이 발생합니다. 따라서 근로계약서 작성 여부를 개인의 책임에만 맡기기보다, 플랫폼이 적절한 시점에 계약을 시작하도록 연결할 필요가 있다고 판단했습니다.

서비스 분석

채용과 소통은 연결되어 있었지만,
계약은 여전히 흐름 밖에 있었습니다

알바몬은 공고 탐색부터 지원, 채팅까지 채용 과정의 주요 경험을 하나의 서비스 안에서 제공하고 있습니다. 알바생과 사장님은 채팅을 통해 근무 가능 여부와 시급, 근무일 등의 조건을 자연스럽게 조율할 수 있습니다. 하지만 채용 조건에 대한 대화가 끝난 이후에는 근로계약서 작성으로 연결되는 흐름이 없었습니다. 계약을 진행하려면 사용자가 대화 맥락을 벗어나 별도의 메뉴에서 기능을 직접 찾아야 했습니다. 알바몬에는 이미 채용 공고, 이력서, 채팅과 근로계약서 기능이 존재합니다. 따라서 새로운 기능을 추가하기보다, 이미 존재하는 정보와 기능을 연결해 채용 이후의 계약 과정이 자연스럽게 이어지도록 만드는 것이 우선이라고 판단했습니다.

참고 — 알바몬은 월간 활성 이용자 1,003만 명, 알바 앱 시장 점유율 약 55%를 보유하고 있습니다.

핵심 질문

기능이 없는 것이 아니라면,
왜 사용자는 근로계약서를 작성하지 못하고 있을까요?

근로계약서 기능의 존재만으로는 실제 작성을 유도하기 어려웠습니다. 사용자가 필요한 순간에 기능을 발견할 수 있는지, 작성 과정에서 부담을 느끼지는 않는지, 상대방과 계약 조건을 조율할 수 있는지를 확인할 필요가 있었습니다. 이를 알아보기 위해 사용자 질문과 커뮤니티 게시글을 조사하고, 기존 IA와 사장님·알바생의 계약 플로우를 분석했습니다.

사용자 리서치

근로계약서 기능은 존재하지만,
사용자는 어디에서 확인해야 하는지 모릅니다

사용자 게시글을 조사한 결과, 근로계약서 알림을 받은 이후에도 계약서를 다시 찾지 못하거나, 앱 안에서 계약서를 어디서 확인해야 하는지 질문하는 사례가 반복되고 있었습니다. 사용자는 근로계약서를 자신의 정보와 활동에 해당하는 기능으로 인식해 먼저 마이페이지에서 찾았습니다. 찾지 못하면 채용·지원 관련 메뉴를 탐색했고, 마지막에는 검색이나 외부 지식인에 의존했습니다. 하지만 실제 근로계약서 기능은 다음과 같이 깊은 경로에 위치해 있었습니다.

메뉴 → 개인서비스 → 알바활동관리 → 근로계약서관리

정보구조 분석

사용자가 못 찾는 것이 아니라,
찾을 수 없는 위치에 있었습니다

기존 IA는 근로계약서를 독립적인 핵심 경험이 아닌 ‘알바활동관리’의 하위 관리 기능으로 분류하고 있었습니다. 그러나 사용자 입장에서 근로계약서는 마이페이지에서 다시 확인해야 하는 개인 문서이자, 채용 직후 상대방과 주고받아야 하는 계약 정보입니다. 기능의 성격을 고려하면 마이페이지와 채팅 양쪽에서 접근할 수 있어야 했습니다. 이에 따라 근로계약서를 기존 메뉴의 깊은 구조에서 끌어올리고, 사용자가 실제로 계약의 필요성을 느끼는 두 가지 맥락에 진입점을 배치하기로 했습니다. 이 결정은 단순히 메뉴의 위치를 옮기는 것이 아니라, 사용자의 행동 맥락을 중심으로 정보 구조를 다시 정의한 것입니다.

진입점 재배치
  • 채용 조건을 조율하는 채팅
  • 개인 문서를 확인하는 마이페이지
프로세스 분석

계약서를 찾은 이후에도
작성과 합의 과정은 연결되지 않았습니다

사장님과 알바생의 기존 유저 플로우를 비교한 결과, 세 가지 구조적 한계를 발견했습니다.

채용 완료와 계약서 작성이 연결되지 않았습니다

사장님은 채용이 완료된 후에도 계약서 관리 메뉴에 별도로 접근해야 했습니다. 계약 작성이 채용의 다음 단계로 안내되지 않아 바쁜 상황에서는 작성 시점을 놓치기 쉬웠습니다.

계약 조건에 이견이 있어도 조율할 수 없었습니다

알바생은 전달받은 계약 내용을 확인하고 서명할 수는 있었지만, 근무시간이나 시급이 기존 협의 내용과 다를 경우 앱 안에서 수정을 요청할 수 없었습니다.

근무 조건이 변경되어도 다시 합의하는 절차가 없었습니다

근무시간이나 근무일처럼 실제 현장에서 자주 달라지는 조건을 변경하고, 양측이 다시 확인하는 과정이 제공되지 않았습니다. 이 분석을 통해 근로계약의 핵심은 문서를 작성하는 행위가 아니라, 양측이 같은 조건을 확인하고 합의한 기록을 남기는 과정이라고 정의했습니다.

문제 정의

근로계약의 발견·작성·합의·보관 경험이
서로 단절되어 있었습니다

조사를 통해 발견한 문제는 네 가지 단계로 정리할 수 있었습니다.

  • 사용자가 근로계약서의 위치를 발견하기 어렵다.
  • 길고 복잡한 입력 과정 때문에 작성 부담이 크다.
  • 전달된 계약 조건에 대해 양방향으로 조율하기 어렵다.
  • 체결된 계약의 핵심 내용을 다시 확인하고 관리하기 어렵다.

따라서 각 기능을 개별적으로 개선하기보다, 채용 이후부터 계약 완료 이후까지 하나의 연속적인 경험으로 재설계해야 한다고 판단했습니다.

디자인 전략

계약서를 작성하는 기능에서,
계약을 함께 완성하는 경험으로 전환했습니다

근로계약 과정에서 사용자가 느끼는 질문을 기준으로 네 가지 설계 방향을 도출했습니다.

발견 — “계약서는 어디에 있지?”

사용자가 예상하는 마이페이지에서 계약서를 쉽게 찾고, 채용 대화가 이루어지는 채팅에서도 바로 작성을 시작할 수 있도록 진입점을 재구성합니다.

작성 — “이 많은 정보를 어떻게 작성하지?”

긴 계약서를 단계별로 나누고, 채용 공고와 이력서에 이미 입력된 정보를 활용해 반복 입력을 줄입니다.

합의 — “서로 같은 조건을 확인한 것이 맞을까?”

알바생이 수정이 필요한 조건을 선택해 요청하고, 사장님이 이를 반영한 계약서를 다시 전달할 수 있도록 양방향 조율 과정을 제공합니다.

확인 — “완료된 계약을 다시 볼 수 있을까?”

복잡한 계약서에서 핵심 조건을 카드 형태로 요약하고, 원본 문서는 PDF로 저장해 언제든 확인할 수 있도록 합니다.

해결 방향

알바의 시작을 끝까지 책임지는 알바몬

채용과 계약이 자연스럽게 이어지도록 근로계약을 더 쉽고 확실하게 만듭니다. 사용자는 채팅 안에서 근로조건을 조율하고 계약서 작성을 시작할 수 있습니다. 작성 과정에서는 기존 공고와 이력서의 정보를 활용해 반복 입력을 줄이고, 상대방과 수정 사항을 주고받은 뒤 전자서명으로 계약을 완료합니다. 완료된 계약은 핵심 조건을 빠르게 확인할 수 있는 카드와 법적 원문을 확인할 수 있는 PDF 형태로 함께 보관됩니다.

기능 ① 발견

필요한 순간에 바로 계약을 시작할 수 있도록
접근 경로를 다시 설계했습니다

기존에는 근로계약서를 작성하거나 확인하기 위해 여러 단계의 메뉴를 거쳐야 했습니다. 특히 채용이 완료된 직후에도 계약서 작성으로 이어지는 안내가 없어, 사용자가 직접 기능을 찾아야 했습니다. 근로조건에 대한 대화가 이루어지는 채팅 안에 계약서 작성 진입점을 추가했습니다. 대화로 시급과 근무일을 확인한 직후 계약서를 작성할 수 있어, 채용과 계약 사이의 단절을 줄였습니다. 마이페이지에는 근무후기, 급여명세서와 같은 위계로 근로계약서를 배치했습니다. 계약서를 개인의 근무 기록으로 다시 정의해 사용자가 예상하는 위치에서 쉽게 찾도록 했습니다.

디자인 결정
  • 채팅에서 근로계약서 작성 바로 시작
  • 마이페이지 1 Depth에서 계약서 확인
  • 작성·전달·수정·서명 과정을 채팅 맥락 안에서 연결
기능 ② 작성

긴 계약서를 단계별로 나누어
한 번에 하나의 정보에만 집중하도록 했습니다

기존 근로계약서 작성 화면은 많은 입력 항목이 하나의 긴 페이지에 이어져 있었습니다. 사용자는 전체 작성량을 한꺼번에 마주해야 했고, 정보를 찾기 위해 화면을 반복해서 이동해야 했습니다. 이를 근로자 정보, 근무조건, 임금의 세 단계로 구분했습니다. 각 화면에는 현재 단계에서 필요한 항목만 보여주어 사용자가 한 번에 하나의 판단에 집중할 수 있도록 했습니다. 작성 진행 상황도 단계 표시로 제공해 현재 위치와 남은 과정을 예측할 수 있도록 했습니다. 긴 서식을 단순히 짧게 보이게 하는 것이 아니라, 작성 과정에서 느끼는 인지적 부담을 줄이는 것을 목표로 했습니다.

기능 ③ AI 자동 입력

이미 입력한 정보를 다시 작성하지 않도록
AI가 공고와 이력서에서 필요한 내용을 연결합니다

근로계약서에 필요한 근무지, 업무 내용, 근무시간, 시급 등의 정보는 채용 공고에 이미 작성되어 있습니다. 근로자의 이름, 주소, 연락처와 같은 정보 역시 이력서와 프로필에 존재합니다. 그럼에도 사용자는 계약서를 작성할 때 같은 정보를 다시 입력해야 했습니다. 이 반복 입력을 줄이기 위해 AI가 공고와 이력서에서 계약 항목에 해당하는 정보를 찾아 자동으로 채우도록 설계했습니다. 자동 입력된 내용은 사용자가 직접 확인하고 수정할 수 있으며, 각 정보가 공고와 이력서 중 어디에서 가져왔는지 출처 태그로 표시합니다. AI가 판단 과정을 숨긴 채 계약서를 완성하는 것이 아니라, 사용자가 출처를 확인하고 최종 결정할 수 있도록 보조하는 방식을 선택했습니다.

디자인 결정
  • 공고에서 근무지·업무·근무시간·임금 정보 연결
  • 이력서에서 이름·주소·연락처 정보 연결
  • 자동 입력 항목의 출처 표시
  • 사용자가 확인하고 수정한 뒤 다음 단계로 진행
기능 ④ 합의

계약서는 일방적으로 전달되는 문서가 아니라,
함께 조건을 맞추는 과정이어야 합니다

기존 플로우에서 알바생은 계약서를 받은 뒤 확인하고 서명할 수 있었지만, 협의한 내용과 다른 조건이 있어도 앱 안에서 수정 요청을 하기 어려웠습니다. 이에 계약 조건 중 수정이 필요한 항목을 직접 선택하고, 변경을 원하는 내용과 이유를 작성해 전달할 수 있도록 했습니다. 수정 요청은 기존 대화가 이루어진 채팅으로 전달되고, 사장님은 요청 내용을 확인한 뒤 계약서를 수정해 다시 보낼 수 있습니다. 별도의 전화나 메신저로 이동하지 않아도 계약 조건과 변경 이유가 하나의 맥락 안에 남습니다. 이를 통해 계약이 일방적인 전달이 아니라 양측이 같은 조건을 확인하는 합의 과정이 되도록 했습니다.

기능 ⑤ 전자서명

합의가 끝난 순간 바로 계약을 완료할 수 있도록
마지막 절차를 단순화했습니다

계약 조건에 대한 확인이 끝났다면 사용자가 추가적인 서류를 인쇄하거나 별도의 서명 수단을 찾지 않아도 되도록 전자서명 기능을 제공했습니다. 사용자는 계약 내용과 필수 동의 항목을 확인하고 화면에서 직접 서명할 수 있습니다. 양측의 서명이 완료되면 계약 체결 상태를 명확하게 안내하고, 완성된 계약서를 보관함으로 연결합니다. 작성과 합의에 이어 서명과 보관까지 하나의 서비스 안에서 마무리해 중간 이탈과 계약 누락 가능성을 줄이고자 했습니다.

기능 ⑥ 확인과 보관

긴 계약서는 핵심 조건과 법적 원문을
서로 다른 방식으로 보여주었습니다

근로계약서는 법적 문서이기 때문에 원문 전체를 보존해야 하지만, 사용자가 일상적으로 확인하는 정보는 시급, 근무일, 근무시간, 계약기간과 같은 일부 조건에 집중되어 있습니다. 따라서 계약서 전체를 카드 안에 압축하기보다 두 가지 확인 방식을 제공했습니다. 카드형 계약서에서는 사용자가 자주 확인하는 핵심 조건을 요약해 빠르게 파악할 수 있도록 했습니다. 계약서 원본은 별도의 화면과 PDF로 제공해 필요한 경우 전체 조항을 확인하거나 저장·공유할 수 있도록 했습니다. 계약 진행 중인 문서와 완료된 문서도 구분해, 사용자가 현재 처리해야 하는 계약과 이미 체결된 계약을 쉽게 관리할 수 있도록 설계했습니다.

기대 효과

근로계약을 사용자의 기억이 아니라
서비스 흐름이 챙기도록 합니다

이번 개선안은 새로운 계약 기능을 추가하는 것보다, 이미 존재하는 채용 정보와 사용자 관계를 근로계약 과정에 연결하는 데 집중했습니다.

  • 채용 직후 계약서 작성을 유도해 작성 누락을 줄입니다.
  • 공고와 이력서 기반 자동 입력으로 작성 부담을 낮춥니다.
  • 양방향 수정 요청으로 계약 조건의 불일치를 줄입니다.
  • 계약 변경 기록을 남겨 이후 발생할 수 있는 분쟁에 대비합니다.
  • 카드형 요약과 PDF 보관으로 계약 이후의 관리 경험을 개선합니다.

실제 출시 데이터가 없는 프로젝트이므로 성과를 임의의 숫자로 표현하기보다, 이후 사용성 테스트에서는 다음 항목을 검증하는 것이 적절합니다.

  • 근로계약서 진입점 발견 시간
  • 계약서 작성 완료율과 소요 시간
  • 자동 입력 정보의 수정률
  • 수정 요청 과정의 이해도
  • 체결된 계약의 핵심 조건 확인 시간
회고

계약에서 중요한 것은 빠른 작성보다
서로 같은 내용을 이해하는 것이었습니다

처음에는 근로계약서를 더 쉽게 찾고 작성하도록 만드는 것을 중심으로 문제를 바라봤습니다. 하지만 사장님과 알바생의 전체 플로우를 비교하면서, 계약 경험의 핵심은 서류를 완성하는 것이 아니라 양측이 같은 조건을 확인하고 합의하는 과정에 있다는 것을 발견했습니다. AI 자동 입력 역시 계약서를 대신 작성하는 방식보다, 반복적인 입력을 줄이면서도 사용자가 정보의 출처를 확인하고 최종 판단할 수 있도록 설계하는 것이 중요했습니다. 이 프로젝트를 통해 사용자의 행동이 부족한 이유를 개인의 실수에서 찾기보다, 행동이 자연스럽게 이어지지 않는 서비스 구조를 발견하고 다시 연결하는 것이 프로덕트 디자인의 역할이라는 점을 배웠습니다.
